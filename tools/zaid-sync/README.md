# المزامنة من النظام القديم (zaid_system على qadrs.com)

باتجاه واحد: **القديم ← haya**. المكتب يضلّ يشتغل على النظام القديم، وhaya
بتصير مرآة حيّة إله — الطلاب والمواعيد والحركات المالية بتوصل لحالها.

واللي بتسجّله haya لحالها — الأهداف، التقارير المنشورة، الحضور والتقييم،
رسائل الأولياء — بيضلّ بـhaya وما بيرجع. مش لأنه صعب، لأنه **ما إله مكان
بالقديم أصلاً**: ما في أخصائية معيّنة على جلسة، ولا تقرير إله حالة نشر، ولا
ولي أمر إله دخول.

---

## ليش دفع مش سحب

| | سحب (haya بتجيب ملف) | **دفع (cron بيبعت)** |
|---|---|---|
| بيانات المرضى | بتقعد بملف على رابط بين كل تشغيلة وتانية | ما بتقعد — بتنبعت وبتُستهلك |
| سطح جديد على الموقع الحيّ | رابط جديد | **ولا رابط** — السكربت بينادى من cron |
| لو انكشف المسار | بينقرا الملف | ما في إشي ينقرا |

والسكربت بيقعد **برّا الجذر العام** — لو حدا عرف اسمه ما بيقدر يناديه من
متصفّح، وفيه حارس تاني بيرفض أي تشغيل مش من سطر الأوامر.

## التركيب — مرّة وحدة

### ١ · ولّد التوكن من haya

من حساب الإدارة:

```
POST https://neurex.ps/haya/api/sync/token
```

بيرجّع التوكن **مرّة وحدة وبس**. ما في «اعرض التوكن الحالي» — سرّ بتقدر
تعرضه وقت ما بدك هو سرّ بيضلّ بلقطات الشاشة. انسخه فوراً.

### ٢ · حطّ الملف على qadrs.com

ارفع [`haya_sync.php`](haya_sync.php) عبر FTP إلى:

```
/haya_sync.php          ← جذر الحساب، مش جوّا zaid_system/public
```

وعدّل سطرين جوّاه:

```php
const HAYA_TOKEN = 'التوكن-اللي-طلع-من-الخطوة-١';
const ZAID_ENV   = __DIR__ . '/zaid_system/.env';   // حسب وين حطّيت الملف
```

> `ZAID_ENV` لازم يوصل لـ`.env` تبع zaid_system. إذا حطّيت السكربت بجذر
> الحساب فالمسار `__DIR__ . '/zaid_system/.env'`.

### ٣ · جرّب بلا ما تبعت إشي

من cPanel ← Terminal (أو أي SSH إذا متاح):

```bash
php ~/haya_sync.php schema --dry
```

بيطبع الجداول وأعمدتها وعدد صفوفها، **وما بيبعت ولا بايت**. إذا طلعت
القائمة صح، كمّل.

### ٤ · ابعت الخريطة

```bash
php ~/haya_sync.php schema
```

**هاي أهم خطوة.** haya بتطلب تاريخ ميلاد وجنس وتاريخ التحاق **إلزامية** لكل
طالب، وأنا ما بعرف شو أعمدة `patients` عندك. فالمُستورِد مقفول لحتى توصل
الخريطة وينكتب المقابل عمود بعمود.

بلا هالخطوة أي استيراد بيكون تأليف: يا بيرفض كل صف، يا — وهاد الأسوأ —
بيعبّي الفراغات بقيم مخترعة فيصير بالملف أطفال مواليدهم يوم ما وصلوا.

قلّي لمّا تخلّص وبكتب المقابل.

### ٥ · جدول التشغيل

cPanel ← Cron Jobs ← Add New Cron Job:

```
0 * * * *   /usr/local/bin/php /home/USER/haya_sync.php rows >/dev/null 2>&1
```

كل ساعة. بدّل `USER` باسم حساب الاستضافة، وتأكد من مسار `php` من
`which php` بالـTerminal.

> **ليش ما في خوف من التشغيل المتكرّر:** كل تشغيلة بتبعت كل إشي، وhaya
> بتميّز الصف الوارد بـ`source` + `source_id` — يعني مريض زيد رقم ٤٢ بيصير
> طالب **واحد** مهما اشتغلت المزامنة. انقطعت الشبكة بالنص؟ التشغيلة الجاي
> بتصلّح حالها.

## المتابعة

```
GET https://neurex.ps/haya/api/sync/status
```

بيرجّع: هل الباب مفتوح، هل الخريطة وصلت، آخر ٣٠ تشغيلة بعددها وما انرفض
منها وليش.

**راقبه.** مزامنة بلا سجلّ هي مزامنة ما حدا بيعرف إيمتى وقفت: بتتعطّل بليلة
— توكن انتهى، عمود تغيّر، قرص امتلأ — وبيضلّ المكتب يشوف بيانات بتبيّن
صحيحة، لأنها صحيحة فعلاً **لحتى تلك الليلة**.

### إيقاف

```
DELETE https://neurex.ps/haya/api/sync/token
```

بلا توكن الباب بيرجّع ٤٠٤ كأنه مش موجود.

## أمان

- **ما في سرّ بهذا الملف داخل المستودع.** `HAYA_TOKEN` قيمة وهميّة، والتوكن
  الحقيقي بيعيش بالنسخة اللي على qadrs.com بس. haya خزّنته **مُلبَّداً**
  (`sha256`) — نسخة قاعدة بتنسرّب ما بتعطي مفتاح شغّال.
- **لا تعدّل التوكن بالنسخة اللي بالمستودع.** مستودع haya انسرّب مرّة لـGitHub
  عام ([`neurex-ftp-deploy-rules`]) — وملف فيه توكن بينكتب بالتاريخ للأبد.
- السكربت **قراءة فقط**: ولا `INSERT` ولا `UPDATE` ولا `DELETE` فيه، وبيتحقّق
  من شهادة TLS بلا تعطيل.
- باب `POST /api/sync/zaid` برّا `auth:sanctum` قصداً — اللي بيطرقه مهمّة cron
  مش شخص، وحساب مستخدم لمهمّة مجدولة هو حساب بيقدر يسجّل دخول من متصفّح بلا
  سبب. وهو الباب الوحيد بالـAPI اللي ما وراه مستخدم مسجّل، فمفحوص بـ٨ فحوص
  حيّة في `tools/smoke-test.mjs` و١٩ في `tests/Feature/ZaidSyncTest.php`.
